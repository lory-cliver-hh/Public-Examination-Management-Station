# 部署与异机访问

这个项目现在已经可以：

- 在另一台电脑上单独启动
- 在同一局域网里被另一台电脑访问
- 部署到云服务器后作为网站访问
- 在两台电脑登录同一个账号后共享同一份学习数据

如果你要的是“真正共享同一份数据”，当前版本需要先完成 Supabase 初始化，具体见：

- [Supabase初始化与共享数据.md](Supabase初始化与共享数据.md)

## 当前共享能力

当前版本已经同步到云端的内容包括：

- 课程状态
- 资料目录
- 学习记录
- 待办
- 打卡
- 刷题记录
- 模考成绩
- 倒计时
- 错题本截图与记录

现在的同步模型是：

- 同一账号在两台电脑登录
- 改动写入 Supabase
- 另一台设备刷新页面后即可读取最新数据

还没有做的是：

- 无刷新实时协同

## 方案 1：同一局域网另一台电脑访问

适用场景：

- 两台电脑在同一个 Wi-Fi / 路由器下
- 你希望 A 电脑启动，B 电脑直接打开

操作步骤：

1. 在主机电脑双击 `start-gongkao-manager-lan.bat`
2. 等待终端完成构建并打印局域网地址
3. 在另一台电脑浏览器打开类似下面的地址：

```text
http://192.168.1.23:3001/
```

如果打不开，优先检查：

- 两台电脑是否在同一局域网
- 主机电脑是否允许 Windows 防火墙放行 `3001` 端口
- 主机电脑的终端窗口是否仍然保持运行

## 方案 2：在另一台电脑上单独启动

适用场景：

- 你希望项目完整复制到另一台电脑独立运行

最低要求：

- Node.js 20+
- npm
- Python 3

如果需要错题本 PDF 导出，还要安装 Python 依赖：

```bash
pip install -r requirements.txt
```

启动方式：

```bash
npm install
npm run build
npm run start:local
```

或者 Windows 下直接双击：

```text
start-gongkao-manager.bat
```

## 方案 3：部署到云服务器并发布为网站

当前项目更适合部署到你自己的 Linux 服务器或 Windows 服务器，不建议直接上纯静态托管。

原因：

- 项目包含 Next.js 服务端运行时
- 错题 PDF 导出依赖 Python `reportlab`
- 导出接口需要服务器可写目录 `output/` 与 `tmp/`

### 3.1 使用 Docker 部署

服务器准备：

- 一台可以公网访问的云服务器
- 已安装 Docker
- 已安装 Docker Compose

部署步骤：

```bash
git clone <你的仓库地址>
cd Public-Examination-Management-Station
docker compose up -d --build
```

默认端口：

```text
http://服务器IP:3001/
```

停止服务：

```bash
docker compose down
```

重新部署更新：

```bash
git pull
docker compose up -d --build
```

### 3.2 绑定域名

建议在服务器前面加 Nginx 反向代理，把外部 `80/443` 转发到容器的 `3001`。

示例：

```nginx
server {
    listen 80;
    server_name your-domain.com;

    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

域名正常解析后，可以再给 Nginx 配 HTTPS。

## 方案 4：真正做成“多端同步网站”

如果你最终要的是：

- 家里电脑能用
- 公司电脑能用
- 手机也能看
- 所有设备看到同一份课程进度、错题、记录

那下一步建议是：

1. 接入数据库，例如 `PostgreSQL` 或 `SQLite + Prisma`
2. 把 `localStorage / IndexedDB` 数据迁移到服务端
3. 增加登录体系
4. 再正式发布到公网

否则现在即使挂上域名，它本质上仍然是“可联网访问的浏览器本地单机版”。
